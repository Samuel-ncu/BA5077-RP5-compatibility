每學期第一堂課，我都會問同一個問題：「你最近有沒有遇過一件事，心裡想『要是有個東西幫我看著就好了』？」有人說實驗室的零件老是混在一起，有人說宿舍的洗衣機永遠不知道有沒有人在用。這些小麻煩，就是這門課的起點。

這門課是為**沒有程式背景的商學院同學**設計的。我們不是要你在一學期內變成工程師，而是要你能用一台小電腦、一顆相機、一些程式和 AI 工具，做出一個「能展示、能測試、能改進」的產品原型。

## 這篇會學到什麼

- AIoT 是什麼，資料怎麼從感測器一路走到使用者手上。
- 這門課 56 篇的學習路線。
- 怎麼把一個生活問題，寫成一張可以驗證的產品規劃表。

## 需要的東西

- 紙筆或任何能寫字的工具。
- 3～5 人的小組。
- 今天**不需要** Raspberry Pi，也不用安裝任何東西。

## 一步一步來

### 步驟 1：先弄懂 AIoT 這個詞

**為什麼**：之後每一課都在做 AIoT 的某一段，先有整體的樣子，才知道自己在哪裡。

- **IoT（物聯網）**：讓裝置透過感測器取得資料，需要時再把資料傳給別的裝置或服務。溫度計回報溫度、相機拍到畫面，都是資料來源。
- **AI（人工智慧）**：在這門課主要是指用「模型」處理資料，例如判斷畫面裡可能有什麼東西。**模型會猜錯**，它給的是可能性，不是保證。
- **AIoT**：把「取得資料」和「分析資料」合在一起。有些運算直接在 Raspberry Pi 上完成，這叫**邊緣運算**（不必把資料送上雲端）。

資料的流動可以這樣想（概念示意，不是執行畫面）：

| 順序 | 發生什麼事 |
| --- | --- |
| 1 | 使用者有一個需求 |
| 2 | 相機或其他感測器取得資料 |
| 3 | Raspberry Pi 收到資料 |
| 4 | 做影像處理或 AI 推論 |
| 5 | 顯示結果或發出提醒 |
| 6 | 使用者檢查結果、給回饋，再回到第 1 步改進 |

不是每個產品都需要相機、AI 或網路——**由問題決定要用什麼**，不是反過來。

### 步驟 2：看一眼整學期的路線

**為什麼**：知道終點在哪裡，前面看起來很基礎的課（例如打指令）你就知道為什麼要學。

1. 認識 Raspberry Pi、作業系統與網路，建立一個能操作的環境（新 01～10）。
2. 練習 Python 與 Thonny，確認 OpenCV 可以用（新 11～12）。
3. 用相機取像，練習影像處理、特徵偵測和物件追蹤（新 13～36）。
4. 認識深度學習與 YOLO 物件偵測，比較速度與結果（新 37～45）。
5. 補充應用：語言模型、影像分類、手勢辨識、文字偵測（新 46～56）。
6. 整學期穿插小組專題：設計、測試並展示你們的原型。

### 步驟 3：把想法變成「可以驗證的問題」

**為什麼**：「我想做一個智慧零件盒」太模糊；「在固定燈光下，數出紅色和藍色零件各有幾個」才能測試對不對。

用下面的範例照著填一次：

| 提問 | 範例回答 |
| --- | --- |
| 誰會使用？ | 整理零件的學生 |
| 想解決什麼問題？ | 紅色與藍色零件混在一起，不易快速清點 |
| 需要什麼輸入？ | 相機影像，並確認照明與拍攝位置 |
| 希望得到什麼輸出？ | 紅色、藍色區域的數量或提示 |
| 怎麼檢查效果？ | 在不同光線下比較人工清點和程式結果，記錄錯誤 |

### 步驟 4：小組填一張產品規劃表

**為什麼**：這門課很重視商業思考。如果需求本身不清楚，就算程式跑得起來，也不一定對使用者有幫助。

1. **觀察與描述**：使用者現在怎麼做這件事？卡在哪裡？什麼時候發生？
2. **提出假設**：例如「如果能顯示不同顏色零件的數量，整理時間可能縮短」。注意，這是**待驗證的假設**，不是已經證明的成果。
3. **定義最小成果**：先限定一種光線、固定位置、兩種顏色，只要求在螢幕顯示一次結果。
4. **規劃測試**：準備「有目標」「沒有目標」「容易搞混」三種情況，先由人工記下預期答案，之後和程式比較。
5. **整理價值與成本**：設備、時間、維護要花多少？如果誤判會怎樣？拍到的畫面怎麼保存才不會侵犯隱私？

| 問題 | 你們組要填的內容 |
| --- | --- |
| 目標使用者 | 誰會用？目前怎麼解決？ |
| 問題與使用情境 | 問題在哪裡、何時發生？ |
| 輸入與輸出 | 相機或感測器看到什麼？使用者收到什麼？ |
| 最小可行測試 | 哪些輸入和預期結果能證明基本流程可行？ |
| 成本與限制 | 硬體、維護、隱私及誤判會帶來什麼影響？ |

## 常見問題

| 問題 | 回答 |
| --- | --- |
| 我完全沒寫過程式，跟得上嗎？ | 這門課就是為你設計的。前十篇都在認識電腦和連線，Python 從第 11 篇才開始。 |
| 可以用 ChatGPT 或 Copilot 幫忙嗎？ | 可以，原課程也鼓勵用 AI 工具輔助學習。但請自己讀、自己執行、自己檢查輸出；如果它叫你下載套件或改系統設定，先確認來源和指令在做什麼。 |
| 我們的題目一定要用 AI 嗎？ | 不一定。有些問題用簡單規則就能解決，那反而是更好的設計。 |
| 程式跑成功一次，就代表產品可以用了嗎？ | 不是。「在教室成功一次」和「在真實環境穩定可用」差很多，這就是為什麼要規劃測試。 |

## 小結

AIoT 是「取得資料＋分析資料＋把結果交給人」的組合。這門課從生活問題出發，先想清楚使用者和需求，再一步步學工具。今天的作業只有一張規劃表：寫下使用者、輸入、輸出和你打算怎麼驗證。

**課後自我檢查**：

- 用兩句話說明 AIoT 的資料怎麼從感測器走到使用者。
- 舉一個不需要 AI、只要簡單規則就能解決的問題。
- 說明「系統成功執行一次」和「在真實環境可靠使用」的差別。
