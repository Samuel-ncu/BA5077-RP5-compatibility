# 程式卡住時，我們怎麼找原因？

你按了執行，卻看見紅色英文。這很容易讓人以為自己把電腦弄壞了。先別急：程式只是把遇到的困難寫出來，我們可以像找線索一樣，一次檢查一件事。

## 第一個故事：老師能安裝，我卻找不到套件

以第 14 課為例。舊版 Thonny 可能出現 `No module named 'pkg_resources'`。這句話說的是「管理套件時需要的一個工具找不到了」，不是「OpenCV 已經壞掉」。

先關閉套件管理視窗，回到 Thonny。看看右下角的 Python 路徑，確認是這一課建立的環境。接著依[第 14 課的修復步驟](./第%2014%20課｜在%20Raspberry%20Pi%205%20安裝%20OpenCV.md#步驟-2安裝-opencv)，從上方編輯區開啟該課安裝程式，按綠色 Run。它會使用你正在選用的 Python 安裝教材指定的版本。

為什麼不直接「全部升級」？因為工具的新版本也會改掉舊用法。[setuptools 的官方更新紀錄](https://setuptools.pypa.io/en/stable/history.html#v82-0-0)記載，82.0.0 已移除 `pkg_resources`。本課保留 80.9.0，是為了配合已測過的舊流程；不是版本越新就一定能修好它。

**停下來想一想：**這次找不到的是 `pkg_resources`，如果紅字寫的是 `cv2`，你會先重裝同一個套件嗎？先看下一個故事。

## 第二個故事：明明裝好了，程式卻說找不到 cv2

假設你有兩個工具箱，把 OpenCV 放進 A，卻從 B 執行程式，B 自然找不到。Thonny 和終端機也可能使用不同的 Python。

在 Thonny 上方開新檔，輸入下面兩行，保存後按 Run：

```python
import sys
print(sys.executable)
```

下方會顯示目前使用的 Python 路徑。拿它與安裝程式印出的 `Python:` 比較：如果不同，先到 **Tools → Options → Interpreter** 選回課程建立的環境，再按紅色 Stop/Restart backend，重新執行本課程式。

如果路徑相同，回看安裝輸出，找找是否真的出現完成訊息；下載了檔案不等於已完成安裝。需要向老師說明時，可以執行[環境觀察小程式](./範例程式/看看目前的Python環境.py)，一起看系統、Python 和套件版本。它不會替你安裝或移除東西。

## 第三個故事：找不到可安裝的版本

`No matching distribution found` 表示 pip 沒找到符合這次要求的安裝檔，但原因不只一種。我們先讀它後面接的是什麼名稱：

- 如果是 `install`，pip 把它當成套件名稱了。回到課文使用完整安裝程式；套件搜尋欄只填套件名稱。requirements 檔則每行寫一項套件規格，不要把 `pip install …` 整行放進去。
- 如果是 `numpy`、`torch` 或其他真正的套件名稱，就看看前面是否還有連線、憑證或 Python 版本訊息。網路失敗與版本不相容，要用不同方式處理。

把系統版本、Python 版本、處理器架構和要求的套件版本交給老師一起比對。例如 RP5 的 ARM64 與 Windows 電腦不同，Python 3.13 也不能直接沿用所有 Python 3.11 的安裝檔。老師應先查該套件的官方支援與發行檔，再在新的環境試驗；不要讓你反覆猜版本，也不要在課堂共用環境裡一次升級所有套件。[pip 官方文件](https://pip.pypa.io/en/stable/cli/pip_index/)說明了 Python 版本與平台如何影響可用安裝檔。

如果課文只有「老師電腦已經安裝」，沒有可用的準備步驟，這是教材還沒補齊的地方。請記下停在哪一步，由老師補上路線後再繼續。

## 第四個故事：圖片在電腦裡，程式卻讀不到

先看看程式要求的檔名，再到練習資料夾找同名檔案。副檔名、大小寫，以及它是否真的和程式放在同一資料夾，都要一致。模型、`east_helpers.py` 等輔助程式也需要按課文放好，不能只複製主程式。

如果課文的下載連結出現 404，先停在下載步驟。這表示網址中的檔案已找不到，不是你應該重裝 Python。老師要從原發布者的官方來源確認替代檔，核對模型名稱和程式是否相容，再更新課文；不要拿同名的陌生檔案代替。

如果出現 `FileExistsError`，課程可能是在保護你已完成的作品。保留原圖，改用新的練習資料夾或輸出檔名，便能再做一次。

## 第五個故事：昨天拍過照，今天相機打不開

先把其他使用相機的程式結束，等它釋放相機，再執行一次。若紅字是 `No module named picamera2` 或 `libcamera`，問題發生在取得相機之前；先確認是不是選到了純繪圖環境。相機課需要能讀到系統相機工具的環境，詳見[課程環境的選擇](./Thonny環境與套件安裝.md#選擇今天的學習環境)。[官方 Picamera2 手冊](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf)也說明了這項要求。

若系統列不出相機，再和老師確認接線；接線檢查前要先關機並拔除電源。不要在通電時為了測試反覆拔插排線。

## 最後，把線索交給老師

告訴老師「第幾課、第幾步、我預期看到什麼」，再附上最後一段完整紅字、所選 Python 路徑，以及環境觀察程式的輸出。帳號、密碼或私人畫面不用放進作業。

老師需要把確定可行的處理方式補回原課的同一步，寫明適用版本和成功後應看到什麼；只在接手紀錄留下「已處理」並不能幫下一位同學解決問題。未經實機測試的建議，也要保留待驗證標記。
