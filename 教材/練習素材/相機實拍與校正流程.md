# 相機實拍與校正流程：AI 生成人臉與手

這個練習的素材是**AI 生成的虛構人物**，先顯示在電腦螢幕上，再由 RP5 相機拍攝；不是拍攝真人。此範例用於第 22 課及補充 2、4 課，不能單憑一次結果推論對真實人臉、不同膚色、姿勢或光線的準確率。

## 準備素材與拍照

將 [RP5 相機測試畫面](./RP5相機測試.html)、[AI 生成物件測試圖](./AI生成物件測試.png)和[AI 生成人臉與手](./AI生成臉與手.png)下載到電腦同一資料夾，在瀏覽器開啟 HTML，選擇「AI 生成人臉與手」。將 RP5 相機固定並對準螢幕；拍照時相機不能被其他程式占用。

在 RP5 的練習目錄執行以下命令。此命令會寫入檔案，先確認沒有同名檔案。原始照片可能包含螢幕外的環境，分享前要自行確認內容。

```bash
rpicam-still --nopreview -t 1500 --width 1920 --height 1080 -o facehand-camera.jpg
```

本次在 RP5 實際執行等同拍照命令，取得 1920 × 1080 的 JPEG；完整原始照片因含周圍環境而未上傳。

## 截取與校正測試畫面

將[校正程式](../範例程式/相機測試畫面校正.py)與 `facehand-camera.jpg` 放在同一目錄。程式中的 `source` 四組座標分別是本次照片中測試畫面的左上、右上、右下、左下；**其他拍攝位置須從自己的照片重新量測**。校正並不能保證去除所有私人資訊，公開前還要檢查結果。

```bash
python3 相機測試畫面校正.py
```

本次 RP5 實際輸出：

```text
camera shape: (1080, 1920, 3)
rectified board: (675, 1200, 3)
saved: facehand-board.png
```

本次[已校正的相機實拍素材](../圖檔/facehand-board.png)可供沒有相機的同學下載，直接練習後續偵測。圖中的人物是 AI 合成，檔案是螢幕素材經相機拍攝後的影像。下方各課的偵測與特徵點則由各自的實際程式產生。

## 相機內參校正：10×7 棋盤

棋盤校正用於估計鏡頭的內在參數與畸變。畫面需包含 **10×7 個黑白方格**，因此每張有效影格應找到 **9×6 = 54 個內角點**。一張圖找到 54 點只能證明該視角可用，不能單獨算出可驗收的校正結果。

1. 在電腦瀏覽器開啟本頁的「相機校正棋盤（10×7）」畫面，使用全螢幕並讓四個棋盤角都清楚顯示。該圖是螢幕上顯示的合成校正目標，不是相機實拍照。
2. 在 RP5 先確認相機未被其他程式使用，依相機環境指南建立新的可讀取系統 Picamera2 的 venv，並在其中安裝本課所需 OpenCV。下載[相機校正資料收集程式](../範例程式/相機校正資料收集.py)，放入自己的空練習資料夾。
3. 執行程式後，先確認預覽顯示 54 corners found。每按一次空白鍵只會保存已找到完整 54 點的影格；請移動棋盤與相機，分別收集中間、四角、遠近及不同傾斜角度的視角。程式會以棋盤中心位置、相對大小、長寬比和旋轉角度排除太相似的影格；至少收集 10 個有效且彼此有差異的視角。
4. 收集完成按 c。有效視角不足時程式不會校正；成功時，練習目錄的 calibration-data/ 會包含各影格、camera-calibration.json 參數和 undistorted-preview.jpg。
5. 對照 JSON 記錄解析度、相機矩陣、畸變係數、有效影格數和每視角重投影誤差。檢視校正前後影像；如角度分布太接近或局部誤差明顯偏高，請重新收集更分散的影格，不要只憑一個低 RMS 數字宣稱校正品質足夠。

目前的單張相機畫面曾找到 54/54 角點，但至少 10 個有效視角、參數計算與校正前後比較仍待 RP5 實測。收集程式屬於待驗證的新教學範例，第一次正式採用前需按 Trixie 基線逐步執行並核對輸出。
